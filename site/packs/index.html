Packs

The whole library as .zip archives of plain .gnaural files — for the desktop Gnaural, for other tools, or for safekeeping. Everything in them is built into the studio as well, so these are copies, not the source.

How to use one: download the archive and either open it with the desktop Gnaural, or drop it straight onto the studio with Add pack (.zip) — every session inside joins the browser's preset list and stays there until you remove it.

What is in them, and what is not

  • Original material only. Every session is a tone schedule written for this site. No audio, no narration, no scripts, no manual text from any recording or programme — see Credits.
  • No upstream presets. Gnaural's own preset archive carries no licence statement, so it is deliberately not bundled. If you have those files already, Open .gnaural plays them.
  • Reproducible. The archives are generated from the library by a build script and are byte-deterministic — the same library always produces the same files.
  • Plain XML. A pack is a zip of .gnaural files plus a README. Nothing binary, nothing hidden, nothing to install.

Building your own pack

There is no packaging step on the site for this — a pack is just a zip of .gnaural files, and the studio writes those:

  1. Load or build a session in the studio.
  2. Press Save .gnaural. Repeat for as many sessions as you want in the pack.
  3. Zip them together (any zip tool) with whatever folder structure you like.
  4. Drop the zip back on the studio page — it will be read, listed and remembered.

The reader is deliberately strict: it validates the archive structure, refuses to expand anything beyond a fixed byte budget, and reports a damaged archive instead of half-importing it. It is the app's own reader, so a hostile zip is something the tests have already attacked.
